# Прогноз отклика на банковский вклад

Практика 4 «Развёртывание модели». Команда 6, БИВТ-23-АЭ-2.
Каримов Айдар Тагирович — ML; Добрынин Леон Артемович — данные.

Сервис оценивает вероятность оформления срочного вклада по признакам клиента
и истории предыдущих кампаний. `deposit=1` означает прогноз отклика при заданном
пороге, а не факт открытия вклада. Это учебный прототип для банковского маркетинга.

## Быстрый запуск

Нужны Python 3.12 и Docker для контейнерной части. Команды выполняются из корня проекта.
Артефакты обеих версий уже включены; переобучение доступно одной командой.

```bash
python3.12 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python train.py
python -m pytest -q
python -m uvicorn app.main:app --host 127.0.0.1 --port 8077
```

В Windows активация в PowerShell: `.venv\Scripts\Activate.ps1`.
Документация API: http://127.0.0.1:8077/docs.
В другом терминале:

```bash
curl http://127.0.0.1:8077/health
curl http://127.0.0.1:8077/model-info
curl -X POST http://127.0.0.1:8077/predict -H 'Content-Type: application/json' --data-binary @example.json
python scripts/check_http.py
```

## Данные и преемственность с практикой 3

Использован `bank-additional-full.csv` UCI Bank Marketing: 41 188 строк.
Удалены 12 полных повторов. После удаления, без перемешивания: train 28 823,
validation 6 176, test 6 177. Тестовая часть не используется для оценки или
подбора модели. Все опубликованные метрики относятся к validation.

Входные признаки: `age`, `job`, `marital`, `education`, `default`, `housing`,
`loan`, `pdays`, `previous`, `poutcome`. `duration`, `y` и текущая кампания
во входе отсутствуют. `unknown` сохраняется как категория. Для `pdays=999`
создаётся `was_contacted_before=0`, само значение заменяется на 0.
Pipeline включает это преобразование, StandardScaler, OneHotEncoder и
LogisticRegression(C=1, max_iter=2000, random_state=42).
Обучаемые преобразования подгоняются только по train.

В практике 3 детерминированное преобразование выполнялось перед Pipeline;
здесь оно включено внутрь. Модель переобучена под закреплённые версии библиотек,
старый joblib не загружается с несовместимой версией sklearn.
Precision@10% = **21,07%**, Recall@10% = **19,79%**, AP = **0,1647**:
130 откликов среди 617 выбранных клиентов. Эти показатели совпали с практикой 3.

## Контракт API

| Запрос | Успешный ответ |
|---|---|
| `GET /health` | 200, status, model_loaded, model_version |
| `POST /predict` | 200, probability, deposit, threshold, model_version |
| `GET /model-info` | 200, версия, SHA256 данных и модели, сплит, признаки, метрики |

Ошибочный JSON, пропущенные/лишние поля, неверные категории, числовые строки
и выход за диапазон дают **422**. Не загруженная или повреждённая модель даёт
**503** на всех трёх эндпоинтах. `/health` в таком случае не сообщает ложный успех.
Полная схема допустимых категорий и диапазонов доступна в `/docs`.
Возраст API ограничен 18–100 годами, previous — 0–100, pdays — 0–999;
это явно заданные границы учебного сервиса, а не все возможные значения в мире.

Пример запроса находится в `example.json`. Ответ содержит неокруглённую оценку
вероятности: класс вычисляется по той же величине, которую получает клиент.

### Две версии и смысл порога

- `1.0.0`: первоначальная политика с порогом 0,5.
- `1.1.0`: тот же Pipeline и веса, порог 0,1 из эксперимента практики 3.

При 0,1 на validation выбраны 307 клиентов, Precision = 24,76%, Recall = 11,57%.
Это **не Precision@10%** и не гарантированный бюджет обзвона. Для отбора ровно
10% нужно получить оценки всего списка, отсортировать их и выбрать
floor(0.1 × N); одиночный `/predict` не выполняет этот отбор.
Версия обозначает весь пакет развёртывания: модель, порог и метаданные.
Откат возвращает предыдущую политику решения, а не переобучает модель.

## Docker и откат

Остановите локальный сервер, если хотите использовать тот же порт 8077.

```bash
docker build --build-arg MODEL_VERSION=1.0.0 -t bank-deposit-group6:1.0.0 .
docker build --build-arg MODEL_VERSION=1.1.0 -t bank-deposit-group6:1.1.0 .
docker run -d --name bank-deposit-p4 -p 127.0.0.1:8077:8077 bank-deposit-group6:1.1.0
python scripts/check_http.py --version 1.1.0
```

Откат того же сервиса на предыдущий образ:

```bash
docker stop bank-deposit-p4
docker rm bank-deposit-p4
docker run -d --name bank-deposit-p4 -p 127.0.0.1:8077:8077 bank-deposit-group6:1.0.0
python scripts/check_http.py --version 1.0.0
```

Удаляется только созданный учебный контейнер; образы и файлы сохраняются.
После демонстрации: `docker stop bank-deposit-p4`, затем `docker rm bank-deposit-p4`.
Контейнер работает от UID 10001, публикует порт только на loopback и содержит
HEALTHCHECK. `ARTIFACT_DIR` позволяет локально выбрать другую папку артефактов.

Полная автоматическая проверка обеих версий, HTTP и отката:

```bash
python scripts/demo_deployment.py
```

Нужны собранные образы и свободные порты 18077/18078. Скрипт создаёт только свои
контейнеры с уникальным именем и удаляет их после проверки. Результат —
`evidence/deployment.json`; проверяются статус healthy, версии, пять эталонов,
422, совпадение локальных/контейнерных прогнозов и возврат к исходному image ID.

## Результаты проверки 18 ноября 2026 года

- 34 теста прошли; одно предупреждение устаревшего API сторонней библиотеки.
- Оба Docker-образа собраны и запущены (проверенная платформа Linux ARM64).
- HTTP локально и в контейнере совпадает с эталонами с допуском 1e-8.

## Ограничения

Исторические данные одного банка не подтверждают качество на современных
клиентах. Калибровка вероятностей и A/B-тест не проводились. Это прогноз отклика,
а не причинный эффект звонка. Прототип не имеет авторизации и не предназначен
для публикации открытого API. Joblib-файлы загружаются только из доверенного
пакета проекта. Проверка SHA256 обнаруживает несогласованность файлов,
но не является цифровой подписью.
